# Gouge feature and implementation catalogue

Reviewed 12 November 2026. Nothing is selected or enabled by default. Reply with IDs or use the selection checklist. After your choices, implement and test the selected work, increase the current 1.9.9/versionCode 22, and commit/push to GitHub. The pending authorised local fixes are also part of the future push. No version bump or push occurs at the catalogue stage.

Code found means an implementation exists in the inspected source, not that it was tested on your phone. Early code is incomplete or still needs integration review. Adaptation means a proposed Gouge feature derived from an implementation pattern. X options are research/prototypes, not ready-made production features.

Already in Gouge: device-owner app locks; delayed per-task approvals; temporary app access; installation waits/category exemptions; non-cancellable Focus and action widgets; night curfew/appeal; Chrome whitelist and temporary links; keyword rules/exceptions; Google DNS image filtering and delayed temporary image access; scrolling watchdog; Reddit allowlist; banking mode; uninstall/force-stop/screenshot controls; Curbox presence guard; personal vault; GitHub self-updater. The catalogue lists additions or explicit upgrades, not duplicate implementations of these controls.

Selection rules: existing hard Focus is not weakened by selecting an optional NFC/PIN/breakable-session feature. Remote control requires a companion app or server plus authenticated, replay-safe commands. Notification content/history, location, camera, NFC and new network scope require the permissions or hardware noted on each item. UI hiding depends on app versions. Cumulative usage budgets need usage access. I4 and I5 are alternative DNS implementation paths, or can be selected together for comparison before adopting one.

## App limits and schedules

- [ ] **A1 — Named blocking profiles** [Code found]. Separate Work, Study and Sleep groups containing apps and websites. New group management; Gouge currently has a single Focus setup. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager), [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [BLOK](https://github.com/blokapp-web/blok).
- [ ] **A2 — Flexible weekly schedules** [Code found]. Choose days, multiple time windows and overnight schedules for profiles. Extends Gouge's fixed night curfew; can build on A1. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager), [TimeLimit](https://codeberg.org/timelimit/timelimit-android), [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).
- [ ] **A3 — Daily per-app usage budgets** [Code found]. For example, allow YouTube for a total of 30 minutes per day. Different from the existing limit on each temporary unlock; needs usage access. Sources: [TimeLimit](https://codeberg.org/timelimit/timelimit-android), [Mindful](https://github.com/akaMrNagar/Mindful).
- [ ] **A4 — Shared group budgets** [Code found]. Make several apps share one daily allowance instead of separate allowances. For example, Instagram and YouTube share 30 minutes; needs usage access. Sources: [TimeLimit](https://codeberg.org/timelimit/timelimit-android), [Mindful](https://github.com/akaMrNagar/Mindful), [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).
- [ ] **A5 — Session caps and required breaks** [Code found]. Limit a continuous session, then require a break before using the apps again. For example, 10 minutes of use followed by a 20-minute break. Sources: [TimeLimit](https://codeberg.org/timelimit/timelimit-android).
- [ ] **A6 — Daily app-opening limits** [Code found]. Limit how many times an app can be opened in a day. Counts launches rather than just minutes; needs usage access. Sources: [Mindful](https://github.com/akaMrNagar/Mindful).
- [ ] **A7 — Allowlist-style Focus** [Code found]. Block everything except selected essentials during a session. An additional Focus mode; keep emergency and system essentials available. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [BLOK](https://github.com/blokapp-web/blok).
- [ ] **A8 — Pomodoro cycles** [Code found]. Alternate focus and break phases for a chosen number of rounds. Separate from the existing uninterrupted, non-cancellable Focus session. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [Mindful](https://github.com/akaMrNagar/Mindful).
- [ ] **A9 — Commitment locks on profiles** [Code found]. Lock a profile until a date, for a duration or permanently; allow only tightening. New profile-level commitment rules; permanent mode would be explicitly opt-in. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager).
- [ ] **A10 — Manual bonus-time allowance** [Code found]. Grant a limited extra allowance without removing the underlying daily rule. Bonus time would use Gouge's delayed approval controls. Sources: [TimeLimit](https://codeberg.org/timelimit/timelimit-android).
- [ ] **A11 — Next-day installation approval window** [Code found]. Require explicit app approval during a configured window the next day. Stricter than Gouge automatically releasing a new app when its install wait expires. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager).

## Reels, feeds and browser controls

- [ ] **B1 — Built-in Shorts and Reels blocking** [Code found]. Block short-video sections while preserving other parts of supported apps. Gouge currently has a scrolling watchdog and external Curbox guard; app-version dependent. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [Mindful](https://github.com/akaMrNagar/Mindful).
- [ ] **B2 — Selective feed and section hiding** [Code found]. Hide supported home feeds, comments or other distracting sections. For example, keep YouTube search or Instagram messages; app-version dependent. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).
- [ ] **B3 — Short-video time budget** [Code found]. Apply a daily time limit specifically to Shorts or Reels instead of the whole app. Requires reliable identification of each supported short-video screen. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [Mindful](https://github.com/akaMrNagar/Mindful).
- [ ] **B4 — Short-video count budget** [Code found]. Stop access after a chosen number of short videos or swipes. Distinct from Gouge's rapid-scroll cooldown; counts are heuristic. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).
- [ ] **B5 — Website path-deny rules** [Code found]. Block paths such as youtube.com/shorts while allowing the rest of the site. Gouge supports temporary path approvals, but its ordered domain rules are host-based. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).
- [ ] **B6 — Chrome SafeSearch controls** [Code found]. Add the managed Chrome Google SafeSearch setting. Applies where Chrome supports the policy; not a filter for every app. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager).
- [ ] **B7 — YouTube web Restricted Mode** [Code found]. Add managed moderate or strict Restricted Mode for YouTube in Chrome. Does not force Restricted Mode in the native YouTube app. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager).
- [ ] **B8 — Disable Chrome incognito** [Code found]. Expose managed incognito availability as a protected setting. Does not replace website or keyword rules. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager), [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **B9 — Support Chrome release variants** [Code found]. Manage Chrome Beta, Dev and Canary explicitly as supported browsers. Gouge currently manages the standard Chrome package directly. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager).
- [ ] **B10 — Extra proxy and URL-scheme restrictions** [Early code]. Offer rules for selected translation/archive proxies and data, blob or file URLs. Optional rules may break legitimate pages; no guarantee against every embedded browser. Sources: [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **B11 — Custom UI rule editor** [Code found]. Pick a screen element and define a custom hiding or blocking rule. Advanced feature; selectors and scripts can break after third-party app updates. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).

- [ ] **C4 — Adaptive maths challenge** [Code found]. Require solving a maths challenge before an optional unlock. A friction mechanism, not authentication or proof that a person needs access. - [ ] **C6 — Scheduled grayscale by app** [Code found]. Turn selected apps grayscale while keeping other apps in colour. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox), [BLOK](https://github.com/blokapp-web/blok).
- [ ] **C9 — Sip and stretch breaks** [Code found]. Prompt a short break after using selected apps for a configured period. An optional usage-break aid with configurable usage and break durations. Sources: [Curbox](https://github.com/curbox-app/curbox-android/tree/kt-rewrite/app/src/main/java/neth/iecal/curbox).

## DNS and network features

- [ ] **E1 — Encrypted DNS upstreams** [Code found]. Support user-selected DNS-over-HTTPS or DNS-over-TLS resolvers. Gouge currently forwards Google DNS queries over UDP to the network's resolver. Sources: [Intra](https://github.com/Jigsaw-Code/Intra), [Rethink](https://github.com/celzero/rethink-app), [Firestack](https://github.com/celzero/firestack), [Kids Launcher](https://github.com/siesta5787/kids-launcher-mdm).
- [ ] **E2 — Choose which apps the DNS VPN filters** [Code found]. Expand from Google-only filtering to selected apps or device-wide DNS filtering. Changes filtering scope and may affect other apps; does not decrypt HTTPS content. Sources: [Rethink](https://github.com/celzero/rethink-app), [Kids Launcher](https://github.com/siesta5787/kids-launcher-mdm).
- [ ] **E3 — Per-app internet blocking** [Code found]. Allow an app to open while denying its network connections. Needs integration into Gouge's existing VPN rather than starting a competing VPN. Sources: [Mindful](https://github.com/akaMrNagar/Mindful), [Rethink](https://github.com/celzero/rethink-app).
- [ ] **E4 — Conditional firewall rules** [Code found]. Set network rules for foreground/background use, screen state or metered networks. A larger networking feature, with possible effects on background messaging. Sources: [Rethink](https://github.com/celzero/rethink-app).
- [ ] **E5 — DNS blocklist categories and imports** [Code found]. Offer ad, tracker, malware or content-category lists with update controls. Separate from Gouge's existing manga-domain watchdog and Google image-host blocklist. Sources: [Rethink](https://github.com/celzero/rethink-app), [DNS66](https://github.com/julian-klode/dns66), [Kids Launcher](https://github.com/siesta5787/kids-launcher-mdm).
- [ ] **E6 — System Private DNS filtering floor** [Early code]. Optionally pin and verify a filtering Private DNS provider through device-owner policy. System-wide change; needs compatibility testing with the VPN and captive portals. Sources: [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **E7 — Advanced routing and WireGuard integration** [Code found]. Route selected app traffic through configured WireGuard or SOCKS tunnels. Large optional expansion; external endpoints/configuration are required. Sources: [Rethink](https://github.com/celzero/rethink-app), [Firestack](https://github.com/celzero/firestack).
- [ ] **E8 — DNS health and latency dashboard** [Code found]. Show reader readiness, upstream health, failures and aggregate query timings. Builds on current VPN status and DNS log; keep sensitive domains out of shared reports. Sources: [Intra](https://github.com/Jigsaw-Code/Intra), [Rethink](https://github.com/celzero/rethink-app).

## Implementation and reliability improvements

- [ ] **I1 — Single current-state enforcement worker** [Implementation]. Serialize reconciliation and reject stale policy snapshots before applying them. Improve correctness of concurrent VPN, watchdog and unlock changes without blocking the UI. Sources: [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **I2 — Verified policy results and retries** [Implementation]. Record every failed lock/release operation and read back Android's actual state. Extend Why apps are locked with operation failures and targeted retries. Sources: [OpenWarden](https://github.com/modernn/OpenWarden), [Google TestDPC](https://github.com/googlesamples/android-testdpc).
- [ ] **I3 — Independent recovery steps** [Implementation]. Let each enforcement step fail and retry without preventing the remaining steps. Improves existing Gouge recovery rather than adding a second copy of it. Sources: [OpenWarden](https://github.com/modernn/OpenWarden), [DNS66](https://github.com/julian-klode/dns66).
- [ ] **I4 — Java DNS protocol-library route** [Implementation]. Evaluate reusable packet/DNS parsing, TCP fallback and IPv6 packet support. A smaller alternative to adopting a complete Go networking engine; benchmark before integration. Sources: [DNS66](https://github.com/julian-klode/dns66), [Kids Launcher](https://github.com/siesta5787/kids-launcher-mdm).
- [ ] **I5 — Go networking-backend evaluation** [Implementation]. Prototype Intra or Firestack integration and retain it only if it improves the required behaviour. Choose instead of, or benchmark against, I4; not a promise that Go alone makes the VPN faster. Sources: [Intra](https://github.com/Jigsaw-Code/Intra), [Firestack](https://github.com/celzero/firestack).
- [ ] **I6 — Bounded policy-aware DNS cache** [Implementation]. Cache safely with limits, short negative TTLs and current-rule checks. New blocks and temporary image-access expiry must invalidate or override cached answers. Sources: [DNS66](https://github.com/julian-klode/dns66), [Firestack](https://github.com/celzero/firestack).
- [ ] **I7 — Transactional rule and usage storage** [Implementation]. Use structured, transactional storage and migrations for larger rule/usage datasets. Useful supporting work for profiles and budgets; not a cosmetic rewrite of the current app. Sources: [AndroidPhoneManager](https://github.com/TTeuber/AndroidPhoneManager), [TimeLimit](https://codeberg.org/timelimit/timelimit-android).
- [ ] **I8 — Signed replay-protected remote commands** [Implementation]. Bind commands to the device and atomically store replay counters with policy state. Required foundation for F1/F2/F3; little user-visible value without remote management. Sources: [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **I9 — Permission and data-transparency page** [Implementation]. Generate an accurate page of permissions, inspected signals, retained data and sharing. Registry-driven and tested against actual Gouge behaviour. Sources: [OpenWarden](https://github.com/modernn/OpenWarden).
- [ ] **I10 — Redacted diagnostic export** [Adaptation]. Export service health and policy failures without passwords, page text or private URLs by default. An opt-in Gouge adaptation of the inspected diagnostic patterns. Sources: [DNS66](https://github.com/julian-klode/dns66), [Intra](https://github.com/Jigsaw-Code/Intra), [Google TestDPC](https://github.com/googlesamples/android-testdpc).
- [ ] **I11 — Automated device regression suite** [Implementation]. Test repeated app openings, overlays, wake/reboot, reconnects and allowed-session exits. Expand the current tests so regressions are caught before installing updates. Sources: [OpenWarden](https://github.com/modernn/OpenWarden), [Google TestDPC](https://github.com/googlesamples/android-testdpc).
- [ ] **I12 — Performance and battery guardrails** [Adaptation]. Keep repeatable startup, DNS, scan and idle-work measurements with regression thresholds. Build on existing Gouge profiling; thresholds must come from measurements, not invented scores. Sources: [Intra](https://github.com/Jigsaw-Code/Intra), [Rethink](https://github.com/celzero/rethink-app).
- [ ] **I13 — Curbox companion API integration** [Code found]. Control selected Curbox groups or focus modes and read approved statistics from Gouge. Curbox remains a separate app; requires explicit API approval and compatible version/flavour. Sources: [Curbox API](https://github.com/curbox-app/curbox-android/blob/kt-rewrite/CURBOX_API.md).
- [ ] **I14 — Gouge as a Curbox unlock-condition provider** [Code found]. Make Gouge's approved delay or task a required condition for selected Curbox unlocks. Requires provider registration and a precisely scoped approval; does not expose saved passwords. Sources: [Curbox API](https://github.com/curbox-app/curbox-android/blob/kt-rewrite/CURBOX_API.md).

## Implementation-language findings

- Gouge already uses Rust for password derivation and Java for keyword scanning/DNS dispatch; keep these measured components.
- Curbox and most Android enforcement code use Kotlin; Curbox exposes a versioned Binder/AIDL companion API. Gouge integration needs user approval and capability/version checks, not a second copy of every Curbox feature.
- Mindful uses Flutter/Dart for its UI and Kotlin Android services. Its features do not require rewriting Gouge in Flutter.
- Intra/Firestack use Go network engines through Android bindings; I5 evaluates those concrete components rather than assuming a language switch improves speed.
