# Native task passwords

Install Lock saves an encrypted copy of each task password together with its salted authentication hash when setting up, enrolling, or changing a task password. AES-GCM uses an Android Keystore key, with the exact task scope as associated data. Failure to encrypt prevents the credential transaction from committing. Plaintext passwords are never placed in preferences or scheduled-task records.

Task confirmation uses the native credential directly. Confirming starts a persisted countdown for the exact operation; completing it rechecks the credential and task scope. Changing a password invalidates previously confirmed tasks, even when the replacement happens to have the same plaintext value. Cancellation and reboot behavior remain unchanged. **Settings → Task confirmation delay** defaults to 15 minutes. Changing it uses the existing timing task and its current wait. Confirmed countdowns retain their original duration.

Older versions stored only hashes. Those cannot be converted back into passwords. On first use, a matching legacy saved secret can be imported automatically. Otherwise the task screen asks for the current password once and saves it encrypted after authentication. This does not reset passwords or remove protection. Matching legacy hard locks prevent import; imported credentials retain at least the longest existing delay. Existing legacy scheduled tasks finish using their original secret references and checks. The personal secret vault remains optional and is no longer part of task confirmation.

For **Add allowed subreddits** only, an old hash-only password that is unavailable has a one-time delayed recovery. The user confirms the exact subreddit, then waits at least 15 minutes (or the configured/imported longer delay). At completion the app generates and stores a new native credential and applies that one subreddit addition, including its linked Chrome path, without a second wait. It cannot replace an already-native credential, reset other roles, disable Reddit protection, skip a lockout/hard lock, or execute before its persisted countdown ends. Cancelling cancels the operation; a reboot restarts its wait. Existing rules stay active. Changed/attached credentials invalidate pending recovery references.

Tests cover atomic credential/ciphertext writes, encryption failure, native readiness without any secret-holder access, one-time authenticated upgrades, and invalidation of pending references after password changes. Android tests use isolated preferences.

Opening native task confirmation reads credential metadata without decrypting or hashing passwords. Confirmation still decrypts and authenticates the credential. A bounded process-local cache retains only SHA-256 fingerprints of successful checks, bound to the scope, salt, stored hash, and candidate password. It holds no plaintext passwords, failed guesses, lockout decisions, or reusable task authorization. Password changes invalidate matches through the changed salt/hash; current lockouts are checked before using cached matches. PBKDF2 remains at 120,000 iterations for uncached verification.
